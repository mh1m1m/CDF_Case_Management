## How to read this register

- **Resolution order (§2):** confirmed owner decision → explicit requirement → ADR → governance document → security invariant → safe default → configurable rule → SOURCE_REQUIRED → owner decision. Only R5 goes to the owner.
- **R5** rows were all decided by Fady on 2026-10-13 (DEC-AMB-001…012). Each shows his decision text unedited, its placement, and what holds until the placement lands: a fail-safe that is built today stays until the replacement rule and its negative tests are in place.
- **R1** cites the Q&A number (Q1–Q100), the owner decision (DEC-01…DEC-68 in the UX audit register O17 §17.7 and ADR-016; DEC-F01…DEC-F41 from the Finalization Set of 2026-10-13; DEC-61 and DEC-62 owner cards in ADR-018 and ADR-022) or a settled coordinator ruling. **R1 items are never asked again.**
- **"already open as DEC-nn; not re-asked"** marks a question that the UX audit register already put to the owner and that is still open. This register applies a fail-safe default and does not raise it again.
- **Evidence** names ADRs (`architecture/adr/`), migrations by their last four digits (for example 1890 = `20261007001890_committee_meetings_votes_minutes.sql`), Linear issues, legacy form and CRM status codes, and negative tests N1–N20 from AUTHORIZATION_IMPACT.md.
- **Implementation impact** names the owner: the rebase thread's PR-A (2030/2040, applying DEC-F01–F41) and PR-B (2050 evidence half, 2060 closure, 2070 P11-G3, 2080 P11-G7), the UX thread (2020 access narrowing, Phase 12 screens), or "unallocated" when the coordinator must assign a number. The owner decisions are placed in 2030, 2040, 2050, 2060, 2120 (ADR-048) and 2130 (ADR-049). This register writes no migration.
- **Audit (§24):** every resolution that changes permission, workflow, decision, deadline, evidence or committee participation names its audit event in the implementation column or relies on the command's existing same-transaction audit event (ADR-003, ADR-005). Audit metadata carries codes and ids, never reasons or content (coordinator ruling).
- **Tests (§25):** every CRITICAL and HIGH row has a test ID (T-AMB-nnn) in AMBIGUITY_TEST_MATRIX.md; security rows carry a negative test. EXISTS means a test in the named file already asserts it on main 7130104; EXTEND means an existing test covers part of it and the missing case is named; NEW means it must be written. Every EXISTS and EXTEND claim was checked against its suite by reading it on 2026-10-13; the suites were not run for this document.
