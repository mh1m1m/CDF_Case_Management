# Form Catalogue Rationalization «ترشيد كتالوج النماذج»

- **Status:** Rationalized for all three sources: A (169), C (19) and the owner's 274-item control catalogue D (§5, Phase 11). Every row is reference data in `config.legacy_form_map` (migration 1970, ADR-035), and a test keeps this document and the database equal.
- **Rule (playbook §11–§15; owner answers G1–G5):** the catalogue is a proposed Business Control Catalogue, not a list of screens. No form number or name is kept for parity. Each item maps to exactly one primary target class. Ask once → derive → generate → convert to workflow → convert to component → merge → retire.
- **Taxonomy:** USER_FORM, GUIDED_TASK, WORKFLOW_DECISION, GENERATED_RECORD, GENERATED_DOCUMENT, CHECKLIST, MEETING_MODULE, EVIDENCE_ACTION, NOTIFICATION, APPROVAL_ACTION, SYSTEM_EVENT, REFERENCE_DATA, BCP_ARTIFACT, MERGED_COMPONENT, RETIRED.
- **Tracks** (T01–T09 below) are a control taxonomy for audit and reporting, never sidebar areas (playbook §16). They are this document's working grouping for sources A and C; source D rows carry the catalogue's own 12 tracks.

### Merge rules applied

- **One closure action.** 30+ «إغلاق …» forms differ only by reason; they merge into `close_case(outcome_code)` with the outcome catalogue in `CRM_STATUS_RATIONALIZATION.md`.
- **One suspension action.** All «تعليق …» forms merge into `suspend_proceeding(suspension_reason)` and `resume_proceeding`.
- **One preliminary recommendation.** Not-serious, out-of-scope, duplicate, abuse, no-escalation and escalation decisions are outcome codes of one maker → reviewer → approver recommendation (Q13–Q19).
- **Meetings, not forms.** Hearing invitations, reschedules, non-attendance, witness invitations, COI declarations, dissent and casting vote are components of `committee_meeting` (ADR-020).
- **Committee formation forms are retired.** Committees are permanent; a case opens a committee proceeding with an immutable snapshot (Q21, Q30).
- **Generated, never typed.** Minutes, decision notices, evidence registers and referral registers are generated from structured data (playbook §61, owner answer G5: no mandatory official PDF per form; modern generation instead).
