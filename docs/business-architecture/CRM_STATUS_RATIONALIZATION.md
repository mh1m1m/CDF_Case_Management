# CRM Status Rationalization «ترشيد حالات التذكرة»

- **Status:** Analysis complete for every legacy status in the source catalogue; target values are design targets until the migrations in `MIGRATION_PLAN.md` land.
- **Source:** the owner's Drive document "Whistleblowing & Behavioral Misconduct CRM Case Management System" (§8 «توثيق الحالة»), read 2026-10-12. It is a _proposed_ catalogue (owner answer G1: «catalogue مقترح/مصمم داخليًا»), ranked 8th in the playbook's source hierarchy. The rebase prompt says 140 statuses; the document holds **150** (S001–S150, no gaps, no duplicate codes). All 150 are rationalized here.
- **Also known as:** `STATUS_CATALOGUE_RATIONALIZATION.md` in the rebase prompt.
- **Rule (playbook §7–§10):** no single case-status enum. Each legacy label maps to exactly one semantic type and one target dimension. Display strings such as «قيد التحقيق — بانتظار الرأي القانوني» are _derived_ from structured state, never stored as the truth.
- **Nothing is silently deleted.** OBSOLETE, DUPLICATE and RETIRE rows keep their code so reporting and any future data migration can map legacy values (`config.legacy_status_map`, planned in migration M-STATUS, `MIGRATION_PLAN.md`).

## Reading this table

- **EVENT** rows become audit actions and timeline entries on the object named in _Target Dimension_ (meeting, evidence, mandate, notice). They are not states, so the case never "sits" in them.
- **REPLACE** means a domain object now carries the concept (for example S021 «جلسة استماع» is a `committee_meeting` with purpose HEARING, S034 «بانتظار تشكيل لجنة» is retired because committees are permanent, Q21).
- **SOURCE_REQUIRED** values (who may order an emergency closure, board-referral authority, binding legal opinions, internal settlement basis) stay configurable reference data with status `SOURCE_REQUIRED` until a CDF source exists (playbook §106).
- **Mapping to the current repository:** the 15 `CDF_CASE_V1` states map as follows. REFERRAL/REGISTERED → `CASE_STAGE=INTAKE`; SCREENING/CONFLICT_CHECK/TRIAGE/JURISDICTION/INVESTIGATION_APPROVAL → `PRELIMINARY_REVIEW` (steps of the preliminary proceeding); INVESTIGATION/FINDINGS → `INVESTIGATION`; GRC_LEGAL_REVIEW → `LEGAL_REVIEW` (after committee, per Q40/Q76); COMMITTEE → `COMMITTEE`; DECISION → `DECISION`; CORRECTIVE_ACTION → `EXECUTION`; CLOSURE → lifecycle CLOSED; ARCHIVE → records_state ARCHIVED. See `TARGET_WORKFLOW_STATE_MODEL.md` §5.
