# Security Rules: control → enforcement → test

Protocol §18–§23, §29, §46–§48, §82–§83, §87. This is the matrix the PR checklist means by "SECURITY_RULES". Every row names where the control is enforced in code and which automated test fails if it is removed. A control with no test is listed as such, never left out.

Classification: SYNTHETIC-DATA REFERENCE IMPLEMENTATION. Controls marked `PRODUCTION_SUBSTITUTION_REQUIRED` are prototype stand-ins; see [`PRODUCTION_MAPPING.md`](PRODUCTION_MAPPING.md). Threat identifiers (T-nn) refer to [`threat-model/THREAT_MODEL.md`](threat-model/THREAT_MODEL.md).

Test paths are relative to `tests/`. `security/*` and `integration/*` run against a real database (`pnpm test:db`); `e2e/*` and `accessibility/*` run in Playwright (`pnpm test:e2e`, `pnpm test:a11y`); unit tests live beside the packages (`pnpm test`).

## 3. Authorization model (RBAC + ABAC)

Authorization is evaluated twice: a pre-check in `@cdf/authorization` so the UI can hide what the user cannot do, and the authoritative check in the database (`authz.*` predicates inside RLS policies and command functions). The UI check is never the control (§87: "no UI-only authorization").

| #    | Rule                                                                                                                                                                                                                                                         | Enforced by                                                                                           | Test                                                                                                                                                                      |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A-1  | A permission is held only through an `ACTIVE` role assignment whose effective dates cover today, by a user whose profile is `ACTIVE`.                                                                                                                        | `authz.has_permission()`, `authz.current_user_id()`                                                   | `security/admin-separation.spec.ts` "suspending a user removes all access in the next transaction"; `security/case-isolation.spec.ts` "revoked users can do nothing…"     |

## 11. Error contract

Command functions raise one of: `CDF_UNAUTHENTICATED`, `CDF_NOT_FOUND`, `CDF_FORBIDDEN`, `CDF_INVALID:<field>`, `CDF_CONFLICT:<code>`. `toAppError()` maps these to user-safe kinds, maps raw `permission denied` to `FORBIDDEN`, and maps anything else to `UNAVAILABLE` with a correlation id. The raw message is logged server-side only.
